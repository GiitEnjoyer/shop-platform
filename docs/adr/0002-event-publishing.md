# ADR-0002: Публикация событий order.created

**Статус:** принято (с запланированным развитием)

## Контекст

После сохранения заказа сервис публикует `order.created` в RabbitMQ (оплата, уведомления). Запись в БД и публикация — две разные системы, атомарности между ними нет.

## Варианты

1. **Публикация после коммита, ошибка брокера не влияет на ответ** (текущий вариант). Простая реализация; при недоступности брокера событие теряется.
2. **Ошибка брокера → 500 клиенту.** Заказ уже сохранён, повтор клиента с тем же `Idempotency-Key` получит 409 — состояние для клиента противоречиво. Отклонено.
3. **Transactional outbox.** Событие пишется в таблицу `outbox` в той же транзакции, что и заказ; отдельный relay публикует и помечает отправленные. Гарантия at-least-once.

## Решение

Вариант 1 с наблюдаемостью потерь:

- publisher confirms + persistent-сообщения: подтверждённое брокером событие не теряется при его рестарте;
- метрика `orders_event_publish_errors_total` и критический алерт `OrderEventsNotPublished`;
- readiness-проба учитывает соединение с брокером, поэтому при длительной недоступности поды выводятся из балансировки.

## Развитие

Переход на outbox (вариант 3) при росте числа потребителей событий. Изменения локальны: `Store.Create` пишет заказ и событие в одной транзакции, публикация уходит в фоновый relay; интерфейс HTTP не меняется.
