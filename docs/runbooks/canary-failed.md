# Runbook: canary отклонён пайплайном

Job `canary:rollback` уже удалил canary-поды и canary-ingress; stable не изменялся. Пользовательское влияние ограничено долей трафика canary (10 % или 50 %) за время анализа.

## Разбор

1. В логе `canary:analyze:*` — какой гейт не прошёл (`error ratio`, `p99`, `no verdict`).
2. Дашборд «Shop / Service SLO and canary», панель «Error ratio: stable vs canary», интервал релиза.
3. Логи canary за период анализа (поды уже удалены — смотреть в Kibana):
   `service:orders AND track:canary AND level:ERROR`.

| Гейт | Частая причина |
|---|---|
| `error ratio` | баг в новом коде; несовместимость со схемой БД; новый обязательный параметр конфигурации не задан в values |
| `p99` | N+1 запросы к БД, отсутствие индекса под новый запрос, холодный кэш |
| `no verdict` | маршрут не получил трафика (ночью, мало пользователей) — повторить релиз днём или поднять `canary.weight` |

## Повторный релиз

Исправление → новый коммит в `main` → новый пайплайн. Перезапускать упавший `canary:start` с тем же образом не нужно: результат будет тот же.

Проверить canary вручную до раскатки на пользователей можно заголовком:

```bash
curl -H 'X-Canary: always' https://shop.example.com/api/v1/orders/<id>
```
